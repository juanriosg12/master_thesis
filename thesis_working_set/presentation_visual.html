The Core Problem

Structure-aware XAI assumes the causal map is correct

THE LITERATURE'S ASSUMPTION

A validated, ground-truth causal graph exists to map feature dependencies perfectly.

Idealized · error-free
THE PRACTITIONER'S REALITY

We rely on automated discovery. Inferred graphs are noisy, imperfect, contested.

Reversed · spurious · bidirectional edges
⚠️
The central question of this thesis — what happens to our explanations when the map is wrong?
Motivation

Shapley values are the gold standard — but symmetry breaks under causality

Traditional Shapley
  • Gold standard for local feature attribution
  • Model-agnostic — any black-box predictor
  • Averages a feature's marginal contribution over all N! orderings
The symmetry flaw
  • Symmetry axiom = every feature is an interchangeable coalition partner
  • When Xi → Xj, correlation is split as if neither caused the other
  • Downstream effect inflated; upstream cause suppressed
SYMMETRIC AVERAGING MIS-CREDITS THE CAUSE
🔧
Structure-aware methods (ASV, CSV, Shapley Flow) embed a causal graph to fix this — they keep Efficiency, Linearity & Null Player, and relax only Symmetry.
Background

Three axioms preserved — one relaxed

✓ PRESERVED BY ALL METHODS
Efficiency
Credits sum to f(x) − baseline
Linearity
Ensemble attributions combine linearly
Null Player
Zero credit for zero contribution
✗ RELAXED TO HONOUR CAUSALITY
Symmetry

Equal credit for equal contribution — fails when one feature causes another.

φi = Σ |S|!(N−|S|−1)!/N! · [ v(S∪{i}) − v(S) ]   v(S)=𝔼[f(X)|XS=xS]
Methods

Three structure-aware extensions — increasing graph dependence

Asymmetric · ASV
lightest
  • Changes which orderings are sampled
  • Value fn unchanged (observational)
  • Graph enters at init only → errors absorbed
Causal · CSV
interventional
  • 𝔼[f | do(XS=xS)] — interventional
  • Absent features re-sampled through parents
  • Each wrong edge corrupts an attribution
Shapley Flow
heaviest
  • Players = directed edges; all |E|! orderings
  • No graph = no game
  • Errors cascade across connected paths
📈
Graph dependence rises left → right. The more a method leans on the graph, the more an imperfect graph can distort its explanations.

Evaluation Framework

Two questions of every explanation: did magnitude or direction change?

MAGNITUDE DIVERGENCE — ΔM

How much the size of an attribution changes, as a fraction of σ̂.

Re-scaling. Alters a feature's weight but keeps the qualitative story.
SIGN DISAGREEMENT — D

Fraction of (instance, feature) pairs whose attribution direction reverses.

Inversion. The explanation tells the affected individual the opposite story.
⊕
A magnitude shift rarely crosses zero; a sign flip happens at the zero boundary. The two flag largely non-overlapping feature populations — both must be measured.

Evaluation Framework

The same two metrics, read at three levels

① Instance
δi,f = |φm,G| − |φref|
  • Signed: + inflates, − suppresses
  • Sign flip = 1 if signs differ
  • Seen in scatter plots
② Feature
ΔMf = (1/σ̂)·√(meani δ²)
  • RMS prevents cancellation
  • ÷ σ̂ → % of output std-dev
  • Seen in heatmaps — which features
③ Global
ΔM = (1/N)·Σf ΔMf
  • Average over all features
  • One number per (method, graph)
  • Seen in scatter & tables
📐
σ̂ normalization: by Efficiency, attributions live on the model-output scale. σ̂ = std of predictions = the total dispersion SHAP distributes. ΔM = 0.10 → "10% of explainable variation" — comparable across both datasets.

Archetype 2 · Directed edge inversion

A reversed edge transfers causal credit — X47 → X21

X47 — True 3in/1out · PC correct · LiNGAM 0in/5out (apparent root)
Flow+PC agrees with oracle · Flow+LiNGAM: X47 suppressed, X21 inflated
⚙️
Mechanism: LiNGAM reverses X21→X47. Flow then routes X47's credit outward to X21 → X47 under-paid, X21 over-paid. Both contaminated.
💡
Lesson: don't prune the edge — it's real. Invest in resolving its orientation. Correcting direction restores oracle-consistent attributions.

PART IV
What To Do
About It

A default method, a decision rule, and a six-step workflow — all computable without a ground-truth graph.

Conclusion · Method Choice

ASV is the recommended default — but still run the diagnostics

Why ASV?
  • Changes only the permutation space → graph errors absorbed, not inherited
  • Synthetic: ΔMbase <1% σ̂ · Dbase <6% · ΔMoracle <1%
  • Sachs: still best on magnitude — ΔMoracle 2.84% (LiNGAM)
  • No extra compute over standard Monte-Carlo SHAP
Key numbers
MetricSynthSachs
ΔMbase<1% σ̂4–5% σ̂
Dbase<6%16–17%
ΔMoracle<1% σ̂2.84% σ̂
ΔMdisc1.07% σ̂8.46% σ̂

On Sachs, erk & pka still show elevated ΔMdisc even under ASV — the framework pinpoints exactly which nodes to validate.

⚠️
CSV & Flow only with a validated graph. CSV: each wrong edge corrupts via do-calculus. Flow: errors cascade along every path. Use them only when ΔMdisc & Ddisc are low across all features — or domain experts confirm the structure.
Practical Recommendations

A six-step workflow — no oracle required

1
Two algorithms

Run PC and LiNGAM on the same data. Never trust one alone.

2
Baseline alarm

ΔMbase, Dbase vs Traditional → structurally sensitive features.

3
Cross-disc alarm

ΔMdisc, Ddisc. High on both = top priority.

4
Validate nodes

Domain knowledge resolves edge orientation. Don't prune real edges.

5
Choose method

Default to ASV — lowest risk under any graph quality.

6
Upgrade if clean

CSV/Flow only when disc-metrics low everywhere & edges validated.

🔑
Steps 1–3 need no ground-truth graph — just two discovery runs and a Traditional Shapley baseline. Fully computable in any real-world setting. Report ΔMbase & Dbase alongside any structure-aware explanation to keep the modelling decision auditable.
