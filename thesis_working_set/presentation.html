Motivation

The World Practitioners Face

Standard Explainability

  • Shapley values: gold standard for local feature attribution
  • Model-agnostic, works with any black-box predictor
  • Satisfies four cooperative-game axioms

The Symmetry Problem

  • Symmetry axiom treats all features as interchangeable
  • Averages over all N! orderings with equal weight
  • When Xi causes Xj: correlation mis-credited to downstream effect
  • Inflates credit of descendants, suppresses upstream causes

Four Shapley Axioms

AxiomMeaning
EfficiencyCredits sum to f(x) − baseline
LinearityEnsemble attributions combine linearly
Null PlayerZero credit for zero-contribution features
Symmetry ✗Equal credit for equal contribution — fails under causality

Structure-Aware Methods

  • ASV, CSV, Shapley Flow embed causal graph into attribution
  • Preserve Efficiency, Linearity, Null Player
  • Relax Symmetry to honour causal ordering
  • Promise more faithful local explanations
Problem Statement

The Practitioner's Dilemma

Structure-Aware methods require a causal graph

  • In practice, the true graph is never directly observable
  • Practitioners rely on automated causal discovery algorithms
  • Estimated graphs are noisy — false positives, false negatives, mis-orientations

The missing piece

  • No existing framework measures how much attribution quality degrades as a function of graph imperfection
  • Practitioners have no principled basis to decide whether a discovered graph improves or distorts explanations

This thesis

  • Builds a replicable experimental pipeline
  • Measures attribution change via Magnitude Divergence (ΔM) and Sign Disagreement (D)
  • Works for any dataset, model, and discovery algorithm

Background

Traditional Shapley Values

Core idea — Cooperative Game Theory

  • Players = input features; Payoff = model prediction
  • Coalition S: features with their real values; absent features marginalized over background data
  • Marginal contribution: Δ when feature i joins coalition S
  • Attribution = average marginal contribution over all N! orderings
φi = Σ |S|!(N−|S|−1)! / N! · [v(S∪{i}) − v(S)]

v(S) = 𝔼[f(X) | XS = xS] — observational coalition value

Focus: Local Attribution

  • Explains one prediction for one instance
  • Credits sum exactly to f(x) − baseline (Efficiency)
  • Model-agnostic: any black-box f(·)

Four Shapley Axioms

AxiomMeaning
EfficiencyCredits sum to f(x) − baseline
LinearityEnsemble attributions combine linearly
Null PlayerZero credit for zero-contribution features
Symmetry ✗Equal weight for equal contribution — fails under causality
Background

The Symmetry Problem Under Causality

The Symmetry Failure Under Causality

  • Uniform weighting over all N! orderings = Symmetry axiom
  • If Xi → Xj, they are not interchangeable coalition partners
  • Symmetric averaging inflates downstream Xj at the expense of upstream cause Xi
  • Correlation between cause and effect is split as if neither caused the other

What Structure-Aware Methods Fix

  • Each method modifies exactly one ingredient of the Traditional recipe
  • All three preserve Efficiency, Linearity, Null Player
  • Symmetry is the only axiom that changes
🔷
The open question: When the causal graph injected into each method is imperfect, how much does the Symmetry fix hurt vs help?

Metrics

Why Two Metrics?

Magnitude Divergence (ΔM)

  • Per-feature RMS of |φm,G| − |φref|, normalised by σ̂
  • Measures how much the size of an attribution changes
  • Concentrates on a handful of dominant features
  • ΔM = 0.10 means "10% of model output σ̂ difference"

Sign Disagreement (D)

  • Fraction of (instance, feature) pairs where sign flips vs reference
  • Measures whether the direction of attribution reverses
  • A sign flip = explanation says the opposite qualitative story
  • Fires on features near zero — invisible to ΔM

Why they flag different features

  • High-magnitude features: large attributions absorb structural changes without crossing zero → ΔM fires, D stays low
  • Near-zero features: a small graph-induced shift is enough to flip sign without leaving a large RMS footprint → D fires, ΔM stays low
  • The two populations are largely non-overlapping

Metrics

Three Comparison Tracks

_base Practitioner

Reference: Traditional Shapley (no graph)

How much does injecting a causal graph move attributions away from the graph-free baseline?

  • ΔMbase: magnitude shift caused by graph injection
  • Dbase: fraction of signs that flip when graph is added
  • Computable without any oracle — just run Traditional Shapley

_disc Practitioner

Reference: same method, opposite discovered graph (PC ↔ LiNGAM)

How stable are attributions when you switch from one discovery algorithm to another?

  • ΔMdisc: magnitude instability between the two graphs
  • Ddisc: sign instability between the two graphs
  • Only requires two discovery runs on same data

_oracle Validation

Reference: True DAG / Consensus DAG

How closely does a discovered graph recover the ground-truth attributions?

  • Available only in controlled experiments
  • Confirms whether _base and _disc signals were pointing at genuine problems
  • Post-hoc validator, not a practitioner tool
Key insight:  _base and _disc together approximate what _oracle would reveal — without needing a ground-truth graph
Metrics

Three Measurement Levels

① Instance level

δrefi,f = |φm,Gi,f| − |φrefi,f|

  • Signed: positive = graph inflates, negative = suppresses
  • Sign disagreement: 1 if signs differ, 0 otherwise
  • Visible in scatter plots

② Feature level

ΔMreff = (1/σ̂) √(mean over i of δ²)

  • RMS collapses instance gaps — prevents cancellation
  • Divided by σ̂: % of model output standard deviation
  • Visible in heatmaps — identifies which features are affected

③ Global level

ΔMref = (1/N) Σf ΔMreff

  • Average over all features
  • Single number per (method, graph) combination
  • Visible in scatter plots and summary tables
Convention:  Tables → global level  |  Heatmaps → feature level  |  Scatter plots → instance or global level

σ̂ normalization: By Efficiency, all attributions sum to f(x)−baseline, so attributions live on the model output scale. σ̂ = std of predictions over the test set = total dispersion the SHAP budget distributes. ΔM = 0.10 means "10% of explainable variation" — comparable across both datasets regardless of raw units.

Case Studies

The Two-Signal Alert System

Four archetypal failure modes — each identified by a distinct alarm pattern in the accessible metrics

🔶
Alarm 1 — ΔMbase fires, ΔMdisc quiet
Both algorithms commit the same structural error → correlated failure. Cross-discovery cannot detect it. Example: X24
🔷
Alarm 2 — Both ΔMbase AND ΔMdisc fire
Neighbourhood is influential AND contested. Both algorithms wrong, but differently. Examples: X33, X47, pka, erk
🔴
Alarm 3 — Dbase / Ddisc fires, ΔM quiet
Near-zero attribution feature — small graph-induced shift crosses the sign boundary. Invisible to magnitude metrics. Examples: X10, pkc
Running all four metrics together is what makes the framework diagnostic rather than merely descriptive. Each alarm pattern reveals a structurally distinct failure mode that the others cannot detect.

Case Studies · Archetype 2

Directed Edge Inversion — SHAP Attribution Shift

SHAP scatter (X47 & X21)

Flow+PC agrees with oracle · Flow+LiNGAM: X47 suppressed, X21 inflated

What the inversion does

  • LiNGAM makes X47 an apparent root node (0 incoming edges)
  • Flow then routes X47's credit outward along the inverted edge toward X21
  • Result: X47 under-attributed, X21 over-attributed — both wrong
🔷
Lesson: Don't prune the X21–X47 edge — it's real. Invest in resolving its correct orientation. Correcting direction (as PC does) restores oracle-consistent attributions without discarding structural information.

Conclusion

ASV: The Recommended Default

Sachs discovery scatter — ASV lower-left (most stable) but feature-level metrics still flag erk & pka even under ASV

Why ASV?

  • Changes only the permutation space — graph errors absorbed, not inherited
  • Synthetic: ΔMbase <1% σ̂, Dbase <6%, ΔMoracle <1%
  • Sachs: still best on magnitude — ΔMoracle=2.84% under LiNGAM
  • No additional computational cost over standard Monte Carlo SHAP

Even ASV needs the diagnostic framework

  • On Sachs, erk and pka show elevated ΔMdisc even under ASV
  • Small networks: each discovery edge constrains a larger ordering fraction
  • The framework identifies exactly which nodes to validate

CSV & Flow: Only With a Validated Graph

CSV & Flow Require Graph Validation

  • Use only when ΔMdisc and Ddisc are low across all features
  • Or when domain experts have validated the specific graph structure
  • CSV: each wrong edge corrupts an attribution via do-calculus directly
  • Flow: errors cascade along all connected paths simultaneously

Decision Rule

  • Start with ASV — lowest risk under any graph quality
  • Run the diagnostic framework first, even with ASV
  • Upgrade to CSV/Flow only after feature-level validation passes
Practical Recommendations

Practitioner Workflow — Steps 1–3

1
Run two discovery algorithms on the same data (e.g. PC and LiNGAM). Never rely on a single algorithm.
2
Compute baseline comparison (ΔMbase, Dbase) vs Traditional Shapley. Identify features where graph injection causes large magnitude shifts or sign flips — first alarm.
3
Compute cross-discovery comparison (ΔMdisc, Ddisc). Features high on both _base and _disc have a neighbourhood that is influential AND contested — double alarm, highest priority.

What these steps give you

  • Step 1: Two independent graph estimates — required for cross-discovery metrics
  • Step 2: Baseline alarm — identifies which features are structurally sensitive
  • Step 3: Cross-discovery alarm — identifies features that are additionally graph-contested
🔷
Steps 1–3 require no ground-truth graph and no oracle. They only need two discovery algorithm runs and a Traditional Shapley baseline — fully computable in any real-world setting.
Practical Recommendations

Practitioner Workflow — Steps 4–6

4
Validate flagged nodes: consult domain knowledge, literature, or experts to resolve edge orientation or presence for contested neighbourhoods. Do not prune real edges — resolve their direction.
5
Choose Shapley method: use the validated graph. Start with ASV as the default — lowest risk under any graph quality.
6
Upgrade to CSV or Flow only if the cross-discovery metrics are low across all features AND most discovered causal relationships are validated and make domain sense.

Default recommendation

ASV — delivers oracle-level alignment, absorbs graph errors, zero additional computational cost. Always run the diagnostic framework first, even with ASV.

Reporting

Report ΔMbase and Dbase alongside any structure-aware explanation to make the causal modelling decision transparent and auditable.

Key insight

ΔMbase + Dbase only require a Traditional Shapley run as reference.
ΔMdisc + Ddisc only require two discovery runs on the same data.
Both are fully computable in any real-world setting.
